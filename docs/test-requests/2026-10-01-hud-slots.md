# The HUD slot machine made general, with the slot-4 tank meters, the bolt alert, Giant Clank's bar, the boss meter and the best-time lines

## 1. Summary
G-UI-011. The 13-slot HUD (`queue_animation_update` and its loop) was ported for health / bolts / weapon / prompt only. Now:
- **General machinery**: `Request` (slot, flags, icon, element, max), the game-mode-5 slot rule, release by handle
  (`fun_001ff480`), the generic init `0x24b418`, value + size `0x24b318`, the counting update `0x24b538` (√ step with a
  byte accumulator), the jump update `0x24b7c0`, placement `0x24b108` and the slide-in / slide-out tables `0x24b170`.
- **A call channel** (`rc_game::hud::calls`): the classes record slot calls in `Services::hud`, the engine's menus in
  `HudFeed::calls`; the HUD replays them before its next tick. Hero-side callers are derived from the state each tick.
- **Elements**: oxygen meter (slot 4), Morph-o-Ray meter (slot 4), Suck Cannon held count (slot 4), nearby-bolt alert
  (slot 7, the Metal Detector's element 7), Giant Clank's energy bar (slot 0 in body 2), the boss meter (slot 6:
  levels 06 / 07 / 13 / 18 draw), the race best-time lines under the slot-12 prompt (levels 5 / 16).
- **Callers**: health only on damage (no longer on a gain), L3 / the quick select's △ / `PageMenuClose` keep health +
  bolts up 180 ticks, `NpcTalkUpdate`'s bolt counter (60 ticks), `CollectBolt`, `HudBoltAlertShow`.
- **Finding**: the boss meters are **slot 6**, not slot 4 (slot 4 holds the three tank meters). The race HUD itself
  (slots 0 / 5 / 7 on levels 5 / 16) is the races' own level code (G-LVL-007).
- **Plug-and-play**: a boss calls `svc.hud.boss_meter(key, value, max)` every tick (key: any id, e.g. its moby id;
  value: its health word) and `svc.hud.set_flags(Request::boss(key, max), 0)` when done. Any element: `svc.hud.queue(r)`,
  `keep_up(r, n)`, `set_flags(r, f)`, `release(r)`, `data(key, v)`.

## 3. Behaviours to verify

Constants: `ScaleTicks(n) = n` (NTSC). Screen 512 × 416. Slot anchors: 0 (20,15) bits 5, 4 (492,208) bits 8, 6
(256,376) bits 2, 7 (492,376) bits 0xa, 12 (142,50) size 180×66.

### B1. queue / compare / pending / immediate apply
- **Claim:** `queue_animation_update` (0x24ad98) re-arms only when flags, icon, element (init/update/draw/data) or max
  differ: new handle (counter 0x17e958 + 1), pending, timer 0, slide 0, alpha 0; an identical request returns the same
  handle and changes nothing. Applied when +0x6c reaches −6, or at once when `req.flags & slot.flags & 0x20`.
- **Setup:** `HudState::new(assets)`. **Trigger:** `queue_req(Request::OXYGEN)` twice; then a different max.
- **Expect:** same handle twice; the third returns handle+1; pending until the loop brings +0x6c to −6.
- **Edge:** game mode 5 (`Inputs::mode = 5`): slots other than 0 / 2 return 0 and keep their request; slots 0 / 2
  accepted. **Method:** unit test on `HudState`.

### B2. release (`fun_001ff480`) and set-flags / keep-up by request
- **Claim:** releasing a handle queues `(slot, 0xffff, Empty, max 0)`; `Call::SetFlags(r, 0)` drops flag 0x10 (applied
  slot: flags now; pending: on apply); `Call::KeepUp(r, n)` raises the timer to ≥ n only when the request is applied
  (pending → no-op). A call whose request is no longer the slot's last request does nothing.
- **Method:** unit test via `apply_calls`.

### B3. Generic init / value / size (0x24b418, 0x24b318)
- **Claim:** init: offset (0,0), timer 210; value = min(max(data,…), max) (no data: 99999 both); size: slot anchored only
  left/right (bits & 3 == 0, bits & 0xc ≠ 0) → h += 12·(digits(max)), w ≥ 14; else h ≥ 12, w += 14·digits(max)
  (digits = 1 + ⌊log10 max⌋). Static sizes kept by `reset_slots`.
- **Edge:** the prompt (no data) now has value = shown = 99999 (was 0). **Method:** unit test.

### B4. Counting update 0x24b538 / jump update 0x24b7c0
- **Claim:** each tick value = min(max(data,0), max); when shown ≠ value: timer = 180; if +0x6c > 23: d = |shown −
  value|, n = max(⌊5·√(d/25)⌋, ⌊2d/10⌋) clamped 1..121, acc(u8) += n; if (acc_before + n) & 0xff > 2: shown moves
  toward value by k = acc/2, acc −= 2k. 0x24b7c0: shown = value once +0x6c > 23. Ramp: timer < 5 → (+0x6c = 1 if alpha
  or slide) alpha−− else slide−− (no −6: the loop counts +0x6c down); else slide++ to 8 then alpha++ to 8.
- **Setup:** an applied Boss meter, `apply_calls([Data(k, 100)])`, then `Data(k, 40)`.
- **Expect:** shown steps 100 → 40 over several ticks (first step n = max(⌊5·√2.4⌋=7, 12) = 12 → acc 12 → k 6 …).
- **Edge:** while +0x6c ≤ 23 the shown value does not move but the timer is reset. **Method:** unit test.

### B5. Placement / slide (0x24b108, 0x24b170)
- **Claim:** y −= h/2 unless bit 1 or 2; x −= w (bit 8), −= w/2 (no 4/8), unchanged (bit 4). Then f =
  table[clamp(+0x6c, 0, 23)] (0x17e820 while timer ≠ 0, 0x17e880 at 0; bit patterns in `SLIDE_SHOWN` / `SLIDE_HIDDEN`):
  top y −= ⌊f(h+52)+½⌋, bottom y +=, left x −= ⌊f(w+20)+½⌋, right x +=.
- **Expect:** slot 4 tank (42×192): fully in at x 450, y 112; at +0x6c ≤ 0: x = 512 (off screen). Slot 0 Giant
  (256×64): y = 15 − ⌊f·116 + ½⌋. The bounce table has negative entries (13–16, 18–20, 23): slight overshoot.
- **Method:** unit test on `place`.

## 4. Shared code touched (regression risk)
- `Element` / `Draw` enums (new variants): `menu_render::translate` (arms added), `text_render::execute` (arms added).
- `Inputs` (now `Default`, no `Eq`; `inputs()` test helper uses `..Default::default()`).
- **Behaviour changes (intended, faithful):** health no longer queued on a gain; the prompt's update is now 0x24b538
  (after fading out, +0x6c counts down to −6 over 7 ticks instead of jumping, so a queued replacement applies ~7 ticks
  later); the prompt's value is 99999 (was 0). Weapon request suppressed when body ≠ 0. Existing tests
  `prompt_slot_12_shows_while_requested`, `health_shows_120_ticks_after_damage…` should still pass.
- `Services` gains `hud: Calls` (cloned with Services; ≤ 1024 entries).
- `hud_render::tick_and_build` now takes `ResMut<Play>` / `ResMut<HudFeed>` / `AudioOut` (system ordering).
- `classes/bolt.rs`, `interact.rs`, `buried_bolts.rs`: one extra `svc.hud` push each (no game-state change).
